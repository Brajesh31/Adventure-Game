# 🏛️ Project Governance

Adventure Game is an educational command-line project maintained by its repository owner. This document explains the current decision and contribution approach.

## Project principles

- Correct and predictable game rules.
- Readable code for learners.
- Testable separation between prompts and game state.
- TypeScript and JavaScript consistency.
- Honest documentation of incomplete behaviour.
- Respectful collaboration and responsible security handling.

## Maintainer model

The repository owner coordinates issues, reviews changes, manages releases, and responds to security reports. This policy does not establish a formal committee or guaranteed review schedule.

## Contribution process

Substantial changes should begin with an issue describing the problem, scope, expected behaviour, and validation plan. Contributors should submit focused changes with relevant tests and documentation.

## Review

Reviewers consider gameplay correctness, state handling, type safety, maintainability, validation evidence, and security. A green syntax check alone does not prove a game flow works.

## Disagreements

Discuss technical questions using reproducible examples and trade-offs. The Code of Conduct applies to all project collaboration spaces.

## Security

Follow SECURITY.md for private vulnerability reporting. Sensitive reports should not be disclosed publicly before assessment and remediation.
