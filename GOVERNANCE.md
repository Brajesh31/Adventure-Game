# 🏛️ Project Governance

## Project purpose

Adventure Game is an educational terminal-based adventure simulation. Governance decisions should support clarity, correctness, safe contribution, and an approachable codebase.

## Maintainer model

The repository is maintained by its owner. Contributions are reviewed through GitHub. This document does not create a committee, foundation, elected role, or guaranteed review schedule.

## Decision principles

1. Correct behaviour over cosmetic complexity.
2. Clear rules for fuel, actions, and game outcomes.
3. Maintainability and beginner readability.
4. Consistent TypeScript and JavaScript execution.
5. Tests for deterministic game logic.
6. Honest documentation of current and planned functionality.
7. Responsible handling of security reports.

## Contribution lifecycle

A typical change includes a problem statement, focused implementation, validation, review, and documentation updates. Small documentation corrections may follow a shorter process.

## Review and disagreements

Reviewers should focus on the code, behaviour, maintainability, and test evidence. Technical disagreement should be resolved through reproducible examples and clear trade-offs. The Code of Conduct applies to all project spaces.

## Security decisions

Follow SECURITY.md for private vulnerability reporting. Sensitive reports should not be published publicly before the maintainer has had an opportunity to assess them.

## Governance changes

Changes to this policy should be documented and reviewed for consistency with CONTRIBUTING.md and CODE_OF_CONDUCT.md.
